# 装飾/背景 検証チェックリスト (3LLMスクショ検証の正本)

> 目的: 「達成装飾」を**アイテムアート方式(全猫種で猫が運動アイテムを持つ/着ける)を主役**へ統一する際の、
> スクショ検証の**検証項目**を先に確定し、Claude/Codex/Gemini の3LLMで体系的に採点する。
> ad-hoc な「ギャラリーを見て良い?」を廃し、各項目に合否バーを置く。

確定方針 (2026-06-06): アイテムアート = 主役 / MilestoneBackdrop(コード背景) = 併用 / コードバッジ = 退役 or 補助。

---

## 0. 検証の土台(スクショ前に確定が必要)

- **A. 段階ラダーの正準化** — 現状2系統(MilestoneItem 30/100 と CatDecoration 7/30/100/365)が不一致。
  アイテム方式の**正準ラダー**を1本に決める。提案(要承認):
  - 0日台: アイテムなし(素の猫)
  - 7日〜: 小アイテム(例: リストバンド/タオル)
  - 30日〜: シェイカー(既存アート流用)
  - 100日〜: 王冠(既存アート流用)
  - 365日〜: 最上位(例: 金メダル+王冠 等、365/500を差別化)
- **B. 各段階のアイテム定義** — 上記ラダーの各段に「何を持たせるか」を確定(アート生成の指示書になる)。
- **C. 対象マトリクス** — 11猫種 × 上記段階 × 主要ポーズ(最低 waitingMorning / celebrating)。

> 現状アートは **オレンジ × waitingMorning の shaker / crown の2枚のみ**。
> 全猫種ぶんは未生成 → 本格カバレッジ検証の前に生成が要る(下記フロー参照)。

---

## 1. スクショで3LLMが採点する項目(視覚)

各項目 0–3 点(0=破綻 / 1=要改善 / 2=可 / 3=良)。**全項目2点以上で合格**。

1. **段階識別性** — 各達成段階が一目で「上位」と分かるか(0<7<30<100<365 の序列が視覚で伝わるか)。
2. **構図/被り** — アイテム(シェイカー/王冠等)が顔・手・体・尻尾と不自然に重ならないか。**全ポーズ**で破綻しないか。
3. **二重装飾なし** — アイテムアートと「背景」「(残すなら)コードバッジ」が重複・競合しないか。
4. **背景との調和** — アイテム猫 × MilestoneBackdrop を同時表示で、眩しすぎ/うるさすぎ/チープに見えないか。
5. **トンマナ統一** — 猫種間でアートの線・塗り・陰影・画風が揃っているか(生成のばらつき検出)。
6. **運動テーマ整合** — アイテムが運動文脈に合うか(シェイカー=プロテイン等、アプリの世界観に沿うか)。
7. **ダークモード** — ライト/ダーク両方で背景・アイテムが破綻しないか。

## 2. コード/ビルドで検証(スクショ対象外)

8. **カバレッジ** — 全(猫種×段階×ポーズ)がアセット解決し、欠損は orange フォールバックに落ちる(画像が出ない事故ゼロ)。
9. **アニメ/パフォーマンス** — 背景の粒子/光帯のコスト、reduce motion で静止。
10. **アクセシビリティ** — VoiceOver ラベル(装飾は accessibilityHidden、段階は別途読み上げ要否)。

## 3. 検証フロー(段階的=アート大量生成の前に方式を検証)

1. **パイロット3LLM検証** — 既存の **オレンジ shaker/crown** を使い、項目1–4・6・7 を採点。
   → 「アイテムアート方式が、退役したコードバッジより本当に良いか」を**生成前に**判定。
2. パイロット合格なら → **全11猫種×段階のアイテムアートを Codex で生成**(項目5=トンマナ統一が生成の合否バー)。
3. **本検証3LLM** — 全マトリクスのスクショで項目1–7を採点 → 不合格項目を改善ループ。
4. 項目8–10はビルド/コードで別途検証。

## 4. 各LLMの役割(独立採点)

- **Claude(私)** — 自分で simctl スクショを撮り、項目1–7を採点(自分の目で確認が前提)。
- **Codex** — 同一スクショを項目1–7で独立採点(second-opinion / gpt-5-codex)。
- **Gemini** — 同一スクショを項目1–7で独立採点(画像はワークスペース内に配置して実読を担保)。
- 3者の一致/相違をまとめ、合議で合否判定。
