## ★0. 事前確定済み（2026-06-04, このセッションで客観確認）

実機点検が空振り・堂々巡りにならないよう、**バックエンドは正常**だと先に curl で確定済み:

| 確認 | 結果 | 意味 |
|---|---|---|
| `/auth/v1/settings` | apple=true / google=true / disable_signup=false | プロバイダ有効 |
| Apple dummy id_token → | `validation_failed`（issuer 検出不可） | サーバが**検証を試みている**＝Apple 配線済（`provider_disabled` では**ない**） |
| `delete-account` EF（無認証） | **401** | 関数デプロイ済＋JWT ガード作動 |

→ **もし下の A-2（Apple復元）が実機で失敗したら、原因はサーバ／コードではなく端末側**
（旧ビルド固着・インストール詰まり）と即断定してよい。前回（2026-06-03）も同じ結論だった。

### A-3. 復元が FAIL したときの意思決定ツリー
1. **まず端末側を疑う**（A-0 で backend 正常確定済）: iPhone 再起動 → TestFlight 再 install → 再試行。
2. それでも FAIL かつ画面に `SVC(...) code=...` 等の**本当のサーバエラー**が出る場合のみコード調査
   （nonce / audience / issuer 周り）。
3. **公開を急ぐ／復元に確証が持てない場合のキルスイッチ（コード変更不要）**:
   - `app/GOExercise/GOExercise/Resources/Info.plist` の `FriendsAppleLinkEnabled` を `<false/>` に。
   - → `SupabaseConfig.isAccountLinkingEnabled` が false になり、`FriendsView` の
     `restoreSection`（welcome の復元ボタン）と `backupCard`（バックアップ導線）が**自動で消える**。
     **匿名友達はそのまま動く**。これで「匿名のみ＝確実」な v1.0 を出し、復元検証後に v1.1 で解禁。
   - 影響範囲: Info.plist 1 箇所のみ。要リビルド＆新ビルド番号で審査差し替え。
